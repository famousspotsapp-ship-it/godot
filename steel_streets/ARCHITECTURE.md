# Steel Streets — architecture

How the bundled demo project is actually put together. See
[`README.md`](README.md) for how to run it, the controls, and the gameplay
rules.

## At a glance

| Concern | Implementation |
| --- | --- |
| Retro resolution | `project.godot` sets a 160x144 viewport with `window/stretch/mode="viewport"` and `keep` aspect, upscaled to a 640x576 window. No `SubViewport` node and no palette shader are involved — the four-colour palette is baked into the source PNGs. |
| Renderer | `gl_compatibility` (GLES3), with `default_texture_filter=0` (nearest) and 2D transform/vertex pixel snapping. |
| Persistent state | `GameManager` autoload (`scripts/game_manager.gd`). |
| Animation | `AnimatedSprite2D` + a `SpriteFrames` resource built **at runtime** by `scripts/anim_util.gd`. There is no `AnimationPlayer`, `AnimationTree`, or `AnimationNodeStateMachine` anywhere in the project. |
| Level | Built procedurally in GDScript by `scripts/level_1.gd`; only a stub `.tscn` is authored by hand. |
| Assets | Every PNG and WAV is generated by `tools/gen_assets.py` (Pillow + `wave`). |
| Physics | `CharacterBody2D` bodies plus `Area2D` hitboxes/hurtboxes on named collision layers. |

## Scene flow

`GameManager` owns every scene transition; scenes never call
`change_scene_to_file` themselves.

```
title_screen  ──start──▶  splash_screen  ──▶  level_1
                                               │
                        ┌──────────────────────┴───────────────────────┐
                 boss defeated                                 lives exhausted
                        │                                              │
                     victory  ──any input──▶ title           game_over ──any input──▶ title
```

`scripts/game_manager.gd` holds `lives` (3), `score`, and `current_hp` / `max_hp`
(5) across scenes and emits `score_changed`, `lives_changed`, and `hp_changed`.
`hud.gd` subscribes to those three signals; nothing polls the manager.

## Animation without AnimationPlayer

Each sprite sheet in `assets/sprites/<entity>/<anim>.png` is a single horizontal
strip of equal-sized frames. `scripts/anim_util.gd:build()` takes a spec array
and returns a `SpriteFrames` where every frame is an `AtlasTexture` region of
the strip:

```gdscript
const FRAMES_SPEC := [
    {"name": "idle", "path": "res://assets/sprites/player/idle.png",
     "count": 2, "w": 16, "h": 24, "fps": 3.0, "loop": true},
    ...
]

func _ready() -> void:
    sprite.sprite_frames = AnimUtil.build(FRAMES_SPEC)
    sprite.play("idle")
```

State changes are plain GDScript: the player and enemies call
`sprite.play("walk" | "jump" | "attack" | ...)` from `_physics_process`, and
attack hitboxes are enabled/disabled with explicit timers
(`ATTACK_TIME`, `ATTACK_COOLDOWN`), not by animation tracks.

## Level construction

`scenes/level_1.tscn` only contains a `TileMap`, an `Entities` node, and a BGM
player. `scripts/level_1.gd` (~300 lines) does the rest in `_ready()`:

1. `_build_tileset()` — creates a `TileSet` with a `TileSetAtlasSource` over
   `assets/sprites/tiles/tileset.png` (11 tiles in a one-row strip) and gives the
   three solid tiles a full-tile collision polygon on physics layer `world`.
2. `_paint_background()` / `_paint_foreground()` — layer 0 is sky/brick/window
   decor, layer 1 is the solid geometry described by the `PLATFORMS` table.
3. `_spawn_decor()` — ladders (`Area2D` on the `ladder` layer + stacked
   `Sprite2D`s) and spikes (`Area2D` on the `hazard` layer).
4. `_spawn_pickups()` / `_spawn_enemies()` / `_spawn_boss()` / `_spawn_player()` —
   instantiate the entity scenes at tile coordinates from the const tables
   (`PICKUPS`, `FOOT_SOLDIERS`, `SHURIKEN_THROWERS`, `BOSS_POS`).
5. A `Camera2D` with smoothing and world-bound limits is created in code and
   parented to the player.
6. `_spawn_hud()` adds `scenes/hud.tscn`; the boss is handed to the HUD via
   `call_deferred("_attach_boss_to_hud", boss)` so the HUD is ready first.

Level layout is therefore edited by changing the const tables at the top of
`level_1.gd` (world is `WORLD_W = 100` x `WORLD_H = 9` tiles of 16 px), not in
the editor.

> **Compatibility note:** the level uses the `TileMap` node, which is deprecated
> in Godot 4.3+ in favor of multiple `TileMapLayer` nodes. It still works with
> the engine in this repository (4.7-beta), but a port to `TileMapLayer` is the
> obvious follow-up if `TileMap` is eventually removed. `scripts/projectile.gd`
> also type-checks against `TileMap` and would need updating with it.

## Entities and collision layers

`project.godot` names the 2D physics layers, and the entity scenes rely on those
numbers directly:

| Bit | Layer | Used by |
| --- | --- | --- |
| 1 | `world` | tilemap collision polygons |
| 2 | `player` | `Player` body |
| 3 | `player_hitbox` | `Player/AttackHitbox` (`Area2D`, group `player_attack`) |
| 4 | `enemy` | enemy bodies |
| 5 | `enemy_hitbox` | enemy contact `Hitbox` areas |
| 6 | `ladder` | ladder areas created by `level_1.gd` |
| 7 | `pickup` | question blocks |
| 8 | `hazard` | spikes |

`scripts/enemy_base.gd` is the shared base (`max_hp`, `contact_damage`,
`score_value`, hit flash, death handshake); `foot_soldier.gd`,
`shuriken_thrower.gd`, and `boss.gd` extend it. Cross-entity communication is
duck-typed via groups and `has_method` checks (`take_damage`, `enter_ladder`,
`exit_ladder`), so entities never hold hard references to each other.

## Asset pipeline

`tools/gen_assets.py` (~1000 lines) draws every sprite sheet pixel-by-pixel in
the four-colour Game Boy palette and synthesizes every WAV, so the art and audio
are reproducible from source:

```bash
pip install Pillow
python3 tools/gen_assets.py    # run from steel_streets/
```

Regenerating overwrites the committed PNGs/WAVs in place; the `.import` files
next to them are Godot-generated and stay valid as long as the file names and
sizes do not change.

## Where to make common changes

| Change | File |
| --- | --- |
| Player movement / combat tuning | `scripts/player.gd` (`SPEED`, `JUMP_VELOCITY`, `GRAVITY`, `INVINCIBLE_TIME`, ...) |
| Enemy stats | the `@export` defaults in `scripts/enemy_base.gd` and each subclass scene |
| Level layout, spawns, hazards | const tables at the top of `scripts/level_1.gd` |
| Lives / HP / scoring | `scripts/game_manager.gd` |
| HUD | `scenes/hud.tscn` + `scripts/hud.gd` |
| Input map | `[input]` in `project.godot` |
| Art and sound | `tools/gen_assets.py` |

# Steel Streets — Architecture

Reference for how the bundled `steel_streets/` game project is put together.
Every statement below is taken from the files in this directory; see the file
and symbol names for the authoritative source.

## Engine version

- `project.godot` declares `config/features = PackedStringArray("4.3", "GL Compatibility")`.
- The engine checked into this repository is `4.7-beta` (`version.py` at the repo root),
  so the project is opened by a much newer editor than the one it was authored with.
- Renderer is forced to `gl_compatibility` (also for mobile), with
  `default_texture_filter = 0` (nearest) and 2D transform/vertex pixel snapping enabled.

## Presentation

- Internal viewport is 160x144, window override 640x576, stretch mode `viewport`,
  aspect `keep` — the Game Boy resolution scaled 4x with nearest-neighbour filtering.
- Palette is the four Game Boy greens listed in `README.md`; all art is generated by
  `tools/gen_assets.py` (Pillow + `wave`), so PNGs and WAVs are reproducible from code.

## Global state

`scripts/game_manager.gd` is the only autoload (`GameManager`). It owns run state and
scene navigation:

- State: `lives` (starts at 3), `score`, `max_hp`/`current_hp` (5 HP per life).
- Signals: `score_changed(new_score)`, `lives_changed(new_lives)`, `hp_changed(current, maximum)`.
- Mutators: `reset_run()`, `add_score()`, `set_hp()`, `heal()`, `take_life()` —
  `take_life()` returns `false` when no lives remain.
- Navigation helpers: `goto_title()`, `goto_splash()`, `goto_level()`, `goto_game_over()`,
  `goto_victory()`, each a `change_scene_to_file()` on a `const` scene path.

Scene flow: `scenes/title_screen.tscn` (main scene) -> splash -> `level_1` -> victory or
game over -> back to title on any input.

## Animation

There is no `AnimationPlayer`, `AnimationTree`, or `AnimationNodeStateMachine` anywhere in
the project. Every animated entity is an `AnimatedSprite2D` whose `SpriteFrames` is built at
runtime by `scripts/anim_util.gd`:

```gdscript
static func build(specs: Array) -> SpriteFrames
```

Each spec entry is `{name, path, count, w, h, fps, loop}`; `build()` slices a horizontal
strip PNG into `AtlasTexture` frames. Entities declare a `FRAMES_SPEC` constant and call
`AnimUtil.build(FRAMES_SPEC)` in `_ready()` (see `player.gd`, `foot_soldier.gd`,
`shuriken_thrower.gd`, `boss.gd`, `projectile.gd`).

## Entities

State machines are hand-rolled with float timers inside `_physics_process()` — not driven
by animation callbacks.

### Player — `scripts/player.gd` (`CharacterBody2D`, group `player`)

- Movement: `SPEED = 60`, `JUMP_VELOCITY = -190`, `GRAVITY = 700`, `CLIMB_SPEED = 50`.
- Attack: `attack_timer`/`cooldown_timer`; `$AttackHitbox` (`Area2D`, group `player_attack`)
  is offset `10 * facing` on x and is only monitoring during the middle of the swing
  (`attack_timer < ATTACK_TIME * 0.75`). Damage is read by enemies via `get_attack_damage()`.
- Ladders: `enter_ladder()` / `exit_ladder()` increment a `ladders_overlapping` counter;
  climbing is exited by horizontal input, jumping, or leaving the ladder.
- Damage: `take_damage(amount, from_position)` applies knockback away from the source,
  sets `INVINCIBLE_TIME = 1.2` s, and strobes `sprite.visible` at 12 Hz. Death calls
  `GameManager.take_life()` and either reloads the level or goes to game over.

### Enemies — `scripts/enemy_base.gd` (`CharacterBody2D`, group `enemy`)

Base class (extended via `extends "res://scripts/enemy_base.gd"`) owning
`max_hp`/`contact_damage`/`score_value` exports and:

- `$Hurtbox.area_entered` -> `take_damage()` when the area is in group `player_attack`.
- `$Hitbox.body_entered` -> calls `take_damage(contact_damage, global_position)` on the player.
- Hit flash is `sprite.modulate` toggled between `Color(2,2,2,1)` and white for 0.18 s —
  there is no `ShaderMaterial`.
- `_die()` awards score, defers monitoring off on both areas, and `queue_free()`s.

Subclasses:

| Script | HP | Score | Behaviour |
| --- | --- | --- | --- |
| `foot_soldier.gd` | 2 | 100 | Patrols at 22 px/s, chases at 35 px/s inside `CHASE_RANGE = 70`. |
| `shuriken_thrower.gd` | 3 | 150 | Paces ±14 px around spawn, fires `scenes/projectile.tscn` every 1.6 s within `SIGHT_RANGE = 110`. |
| `boss.gd` | 9 | 1000 | `enum State { PAUSE, WINDUP, CHARGE, RECOVER }` timer cycle; charges at 70 px/s; emits `boss_hp_changed` and `boss_defeated`. |

### Other entities

- `projectile.gd` (`Area2D`): straight-line travel at 110 px/s, 3 s lifetime, despawns on
  `TileMap`/`StaticBody2D` or after damaging the player.
- `question_block.gd` (`Area2D`): consumed by player contact or by a `player_attack` area;
  awards `score_reward` and heals `heal_amount`.
- `hud.gd` (`CanvasLayer`): rebuilds heart `TextureRect`s from `GameManager.hp_changed`,
  formats score as `%05d`, and shows the boss bar only once a boss connects its signals.

No particle nodes (`CPUParticles2D`/`GPUParticles2D`) are used.

## Level construction

`scripts/level_1.gd` builds the whole level in code rather than in a `.tscn`:

- Creates the `TileSet` from `assets/sprites/tiles/tileset.png` (`TILE = 16`) and paints
  background (layer 0) and foreground/solid (layer 1) cells of the single `TileMap` node in
  `scenes/level_1.tscn` over a `WORLD_W = 100` x `WORLD_H = 9` grid, using the `PLATFORMS`
  rectangle table. Note this is the legacy `TileMap` node, deprecated in favour of
  `TileMapLayer` since Godot 4.3, so an editor upgrade prompt is expected.
- Spawns ladders (`LADDERS`), spikes (`SPIKES`, hazard layer 8), pickups (`PICKUPS`),
  enemies (`FOOT_SOLDIERS`, `SHURIKEN_THROWERS`), the boss, the player, a `Camera2D`
  limited to the world bounds, and the HUD.
- Ladder areas call `enter_ladder()`/`exit_ladder()` on any body that has the method.
- `_on_boss_defeated()` transitions to the victory scene.

Changing the level layout means editing the constant tables at the top of `level_1.gd`.

## Physics layers (`project.godot` `[layer_names]`)

1. `world` 2. `player` 3. `player_hitbox` 4. `enemy` 5. `enemy_hitbox` 6. `ladder`
7. `pickup` 8. `hazard`

Cross-entity interaction is done with node **groups** (`player`, `enemy`, `boss`,
`player_attack`, `ladder`) plus `has_method()` duck typing, so layers alone do not
describe the interaction graph.

## Input actions

`move_left`, `move_right`, `jump`, `attack`, `climb_up`, `climb_down`, `start` — each mapped
to keyboard keys and gamepad buttons/axes in `project.godot`. Scripts read them through the
`Input` singleton (`Input.get_axis`, `Input.is_action_just_pressed`).
